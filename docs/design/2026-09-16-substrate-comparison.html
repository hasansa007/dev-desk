Everything B changes, and what it costsB is your design with five edits — not a different design

#The editWhyCost
1Headless is for doors, never a fallback for a task. No adapter → hand off. A gate that means two different things under one control is the one bug this whole redesign exists to remove. A machine with no Node cannot run a task in-app. It could before — in a terminal.
2TaskLaunch is a file, and every executor reads it. The payload is the product; executors are commodities. This is what makes “don’t mimic them” structural instead of a promise. One more on-disk format to keep stable. Worth it — sc --from-file already wants exactly this shape.
3Truth rank stated once: git/.dev > RunJournal > RunEvent. Gate answers are journalled. Three stores now touch a run. Without a stated rank, the stream becomes truth by accident — the exact failure ADR 0011 was written against. An audit line per gate answer. Answers your §8 question 6 with a yes.
4Step 3 splits into 3a/3b/3c — codec+mapper+fixtures, then the pane over fixtures, then wiring. Step 3 as written is the entire risk of the project in one unlookable-at step, in a repo whose rule is look at the result on screen. None. Same work, three commits, each one visible.
5One thing is called Runs. The bottom panel folds into the screen. Elsewhere doesn’t take a slot but shows in the meter. ProjectRuns, DoorRuns and a Runs panel already exist. Two Runs in one app is the problem, not the noun. A rename that touches Sidebar, ContentRouter, README.

Unchanged from your recordmost of it

  • The principle in §4.1, verbatim.
  • Both chats removed (step 1, lands today).
  • SwiftTerm leaves; ⌘T and sign-in leave the app.
  • ACP v1 + version switch; never fs/* or terminal/*.
  • Hand-roll the codec, don’t take the pre-1.0 SPM dependency.
  • Run project becomes a plain Process with a log row.
  • Slot limit, StartQueue, Auto defaults — untouched.
  • Events sidecar stays the phase truth.
  • Antigravity: hand-off only, after the ToS is read.
  • super.engineering: probe sc status --json, hide on failure.
  • No conversation view, no composer outside an ask.
  • Insights untouched (ADR 0030).

Two things neither record decided yetopen

Quit policyACP sessions are children of Dev Desk — quit kills them, exactly as the pty was killed. But for the first time a session id exists, so quit could be survivable: journal it, resume with history next launch. QuitGuard.swift was written for a world where a killed run was lost. That assumption is now false and should be decided, not inherited.
Elsewhere and the slot meterA run handed to Terminal burns tokens Dev Desk can neither see nor stop. B shows it as 3 of 5 running · 2 elsewhere — counted, not governed. The alternative is to let it take a slot, which is a lie in the other direction.
Reading it: A is your record of 2026-09-15 drawn as-is. B is the same design with five edits — the fork is one rule: headless is a different kind of run, not a weaker version of the same one. Red = a path where the app promises something the substrate cannot deliver. Green = a path that can only tell the truth. Blue = the payload, which is the part nobody else builds.
