## Key Findings from Phase 2 Investigation:

### Content Generation Works Perfectly ✅
1. MASTER_PROMPTs generate comprehensive architecture plans when invoked
2. All variants (Next.js, iOS Variant A, Android Variant B) produce detailed phase-based implementation plans
3. Output quality is excellent:
   - Architecture diagrams and module structures
   - Realistic code examples (no hallucinated APIs)
   - Feature development workflows
   - Native integration patterns
   - Performance optimization strategies
   - Risk mitigation approaches

### Root Cause Identified: Invocation & Persistence Gap ❌

**The Problem:** Content generation works, but:
- No automatic trigger when ARCHITECTURE.md is missing
- File creation is implied ("pin decisions"), not explicit
- Pipeline checks for ARCHITECTURE.md but never creates it
- Phase 1 can't distinguish new projects from broken projects

**The Fix (3-part integration):**
1. **Phase 1 (Detection):** Add new-project detection logic
   - Both ARCHITECTURE.md and PROJECT_MAP.md missing = new project
   - Report state clearly (new/partial/full context)

2. **Phase 2 (Bootstrap):** Add automatic architecture generation
   - Detect stack (Next.js/iOS/Android/KMP)
   - Select appropriate MASTER_PROMPT variant
   - Generate and WRITE ARCHITECTURE.md to disk

3. **MASTER_PROMPT (Clarity):** Make file creation explicit
   - Change from "pin decisions in ARCHITECTURE.md" to "CREATE ARCHITECTURE.md"
   - Remove "e.g." ambiguity
   - Define exact output format
